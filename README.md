# BLUEFORM

Интернет-магазин на Nuxt и TypeScript с отдельным Express API. Переход на Express выполняется постепенно: действующие маршруты магазина пока работают в `client/server`.

## Структура проекта

```text
BLUEFORM/
├── client/                  # Nuxt: витрина и будущая админ-панель
│   ├── app/                 # страницы, компоненты, стили и состояние
│   ├── public/              # изображения и другие публичные файлы
│   └── server/              # временный API Nuxt на период переноса
├── server/                  # новый Express API на TypeScript
│   ├── src/
│   │   ├── modules/         # каталог и другие предметные области
│   │   └── middleware/      # общая обработка запросов и ошибок
│   └── tests/               # проверки API и переходных контрактов
├── prisma/                  # общая схема базы и миграции
├── shared/                  # код, пока необходимый обоим приложениям
├── docs/                    # архитектура и план MVP
└── compose.yaml             # запуск приложений и сервисов
```

`client/app` — стандартная папка исходного кода Nuxt. `client/server` и корневой `server` сейчас существуют одновременно: первый обслуживает действующий магазин, второй — новое API. По мере переноса маршрутов в Express временный код Nuxt будет уменьшаться. Перемещать его или удалять раньше проверки замены нельзя.

Старая корневая папка `api`, если присутствует на этом компьютере, содержит локальные остатки прежнего расположения и не относится к текущему проекту. Папки `.nuxt`, `node_modules` и `dist` — создаваемые инструментами рабочие файлы, а не исходный код.

Подробнее: [вся документация](docs/README.md), [архитектура и перенос API](docs/architecture/API-ARCHITECTURE.md) и [план MVP](docs/planning/MVP-PLAN.md).

## Локальный запуск

Создайте `.env` в корне на основе `.env.example` и заполните локальные значения. Нужен Docker с Compose.

```sh
docker compose up -d --build
```

- Магазин: http://localhost:3000
- Express API: http://localhost:3001/api/health
- Документация Express: http://localhost:3001/docs
- Проверка базы: http://localhost:3001/api/ready
- Локальные письма: http://localhost:8025
- Админ-панель заказов: http://localhost:3000/admin/login
- Письма о новых заказах: на `OWNER_NOTIFY_EMAIL` (по умолчанию `admin@blueform.local`), смотреть в Mailpit

После первого запуска заполните каталог и демо-аккаунты:

```sh
docker compose exec web npm run db:seed
```

Seed берёт товары из `client/app/data/catalog-test.json` и создаёт локальных пользователей Better Auth (почта уже подтверждена):

| Почта                  | Роль       | Пароль по умолчанию |
| ---------------------- | ---------- | ------------------- |
| `buyer@blueform.local` | покупатель | `Blueform123!`      |
| `ivan@blueform.local`  | покупатель | `Blueform123!`      |
| `admin@blueform.local` | admin      | `Blueform123!`      |

Пароль можно переопределить переменной `SEED_PASSWORD` в `.env` / окружении контейнера. Эти учётки только для локальной разработки.

Scalar загружает браузерный скрипт с CDN и требует доступа к интернету. Проверка `health` не проверяет базу; для этого используйте `ready`.

## Локальный мониторинг и Directus

Мониторинг и пустой Directus запускаются отдельным профилем, чтобы обычный запуск и CI не требовали дополнительных сервисов. Скопируйте новые переменные из `.env.example` в `.env`, задайте отдельные пароли и случайный `DIRECTUS_SECRET` (не менее 32 символов), затем выполните:

```sh
docker compose --profile observability up -d --build
```

- Grafana: http://localhost:3002, пользователь `admin`, пароль `GRAFANA_ADMIN_PASSWORD`. Готовый дашборд — **BLUEFORM → BLUEFORM — состояние сервисов**.
- Directus: http://localhost:8055, учётная запись `DIRECTUS_ADMIN_EMAIL` / `DIRECTUS_ADMIN_PASSWORD`. Использует отдельную пустую базу, товары и заказы не подключены.
- Prometheus: http://localhost:9090. HTTP-метрики Nuxt и Express доступны на `/metrics` и содержат только метод и статус, без URL и персональных данных.

Дашборд показывает доступность, HTTP-запросы, ошибки 5xx и время ответа, подключения PostgreSQL, нагрузку и использование диска среды Docker, а также журналы. Счётчик ошибок оформления учитывает HTTP-ответы 5xx на создание заказа, ошибки отправки писем — неуспешные попытки SMTP. Оповещения не настроены.

Prometheus хранит метрики 15 дней, Loki — журналы контейнеров `web` и `api` 7 дней. Сборщик Alloy имеет доступ к Docker socket; cAdvisor получает привилегированный доступ к ресурсам Docker. Конфигурация предназначена для локальной разработки, а не публикации в интернет. До рабочего развёртывания настройте защиту доступа, отдельные секреты, резервное копирование и политику журналирования; журналы могут содержать персональные данные. Ресурсы контейнеров на Docker Desktop относятся к Linux-окружению Docker, а не ко всему Windows. Проверки доступности выполняются из Docker и не заменяют внешний мониторинг.

## Directus: первый этап админ-панели

Для работы с товарами и просмотра заказов в Directus запустите профиль `admin` после заполнения `DIRECTUS_SHOP_DB_PASSWORD` и `DIRECTUS_SHOP_SECRET` в `.env`:

```sh
docker compose --profile admin up -d directus-shop-config
```

Панель доступна на http://localhost:8058; вход — `DIRECTUS_ADMIN_EMAIL` / `DIRECTUS_ADMIN_PASSWORD`. При первом входе Directus может предложить указать владельца и принять условия лицензии; это решение принимает владелец проекта.

Откройте [«Товары»](http://localhost:8058/admin/blueform-catalog) через значок вешалки. Здесь можно создать или изменить товар, добавить цвета и фотографии, выбрать размеры, задать цены в рублях и остатки. Первая фотография цвета становится главной; порядок можно изменить. Товар можно сохранить как черновик, опубликовать или отправить в архив. Для новой публикации цвета нужны фотография и хотя бы один активный размер; уже опубликованные товары без фотографии остаются доступными для редактирования. Если остаток изменился при оформлении заказа, сохранение конфликтующего изменения отклоняется: откройте товар заново и повторите изменение. Категории, цвета и размерные сетки выбираются из существующих справочников.

Разделы «Заказы» и «Состав заказов» показывают данные существующего магазина только для чтения. Цены в этих разделах пока указаны в копейках. Смену статуса, трек-номер и комментарий по-прежнему выполняйте в [прежней панели](http://localhost:3000/admin/orders): она применяет проверки, обновляет остатки и отправляет уведомления. Управление доставкой, рассылками и ролями ещё не подключено.

Directus создаёт собственные системные таблицы `directus_*` в базе магазина. Учётная запись Directus может создавать и изменять товары, но не удалять их, имеет только чтение таблиц заказов и не имеет доступа к таблицам паролей и сессий; проверка этих прав запускается при старте. Модуль карточки доступен администраторам Directus. Фотографии хранятся в томе `directus_shop_uploads`, который API подключает только для чтения; вместе с базой необходима резервная копия этого тома. Настройка ожидает применения миграций сервисом web. Не выдавайте дополнительные права без пересмотра ограничений. Прежний пустой экземпляр на порту 8055 и его данные сохранены отдельно. Это локальный контур разработки, не готовый к публикации.

## Проверки

Для проверок нужен Node.js 24 или новее. Установите зависимости корня, клиента и сервера, затем выполните:

```sh
npm ci
npm ci --prefix client
npm ci --prefix server
npm run verify
npm run test:contract
```

`test:contract` требует запущенных сервисов. Полный список проверок и команд исправления — в [документации по качеству](docs/architecture/QUALITY.md). Команды `npm run dev:client` и `npm run dev:server` запускают соответствующее приложение локально. Вне Docker нужно отдельно обеспечить доступ к PostgreSQL и передать необходимые переменные окружения.
