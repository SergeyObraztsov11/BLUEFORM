# Качество кода

- Используй понятные имена для переменных, функций, компонентов и файлов. Названия должны отражать их назначение.
- Предпочитай простую и понятную структуру. Держи связанный код рядом и разделяй ответственность там, где это упрощает понимание и поддержку.
- Старайся, чтобы функции и компоненты выполняли одну понятную задачу. Не дроби код на слишком мелкие части, если это затрудняет чтение.
- Избегай неоправданного дублирования значимой логики, но не объединяй похожий код, если это создаёт запутанную абстракцию.
- Пиши комментарии для объяснения причин и неочевидных решений, а не для пересказа очевидного кода.
- Явно и уместно обрабатывай ошибки; не скрывай их молча.
- Добавляй или обновляй тесты, когда они помогают проверить важное поведение и защитить его при изменениях.
- При работе над задачей улучшай соседний код, если это уместно и не расширяет задачу без необходимости. Не переписывай существующий код только ради соответствия этим принципам.
