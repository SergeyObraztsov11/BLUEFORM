# Правила работы с Git

Эти правила действуют для проекта BLUEFORM.

## Авторство

- Создавай коммиты только от имени владельца проекта, используя настроенные в Git `user.name` и `user.email`. Не подменяй автора или коммиттера именем агента.
- Не добавляй в сообщения коммитов подписи или строки `Co-authored-by` от имени ИИ или агента.
- Если имя или email автора не настроены либо возникли сомнения, кому должен принадлежать коммит, уточни у владельца проекта до его создания.

## Сообщения коммитов

- Используй формат Conventional Commits: `тип: краткое описание` или `тип(область): краткое описание`.
- Основные типы: `feat` — новая функциональность, `fix` — исправление, `docs` — документация, `style` — форматирование без изменения поведения, `refactor` — рефакторинг, `test` — тесты, `chore` — обслуживание, `build` — сборка и зависимости, `ci` — настройки CI, `perf` — производительность.
- Пиши короткое и понятное описание в повелительном наклонении; язык описания выбирай по контексту проекта. Например: `feat(cart): add quantity controls` или `fix(auth): исправить вход`.
- Объединяй в один коммит логически связанные изменения. Перед коммитом проверяй состав изменений и не включай секреты, локальные файлы окружения и результаты сборки.

## Ветки

- Для каждой новой задачи используй отдельную ветку от актуальной основной ветки, если пользователь не попросил иначе. Продолжение той же задачи выполняй в её существующей ветке.
- Имена веток: `тип/краткое-описание`, строчными латинскими буквами, слова через дефис. Например: `feat/product-filters`, `fix/cart-total`, `docs/setup-guide`, `chore/update-dependencies`.
- При наличии номера задачи допускается добавлять его: `feat/123-product-filters`.
- Не переключай ветки и не переноси изменения так, чтобы потерять или смешать незакоммиченные изменения пользователя.

## Отправка изменений

- Перед коммитом и отправкой проверяй состояние репозитория, текущую ветку и назначение удалённого репозитория.
- Не выполняй `push --force`, не переписывай опубликованную историю и не удаляй удалённые ветки без явного запроса пользователя.
- После создания коммитов отправляй их в соответствующую ветку удалённого репозитория, если пользователь не попросил оставить изменения локально. Для новой ветки настрой upstream.
- После завершения задачи и необходимых проверок самостоятельно объединяй её ветку с основной и отправляй обновлённую основную ветку, если пользователь не попросил иначе. Перед объединением проверяй состояние обеих веток и сохраняй чужие изменения.
- После отправки и объединения сообщай название ветки и результат. Если проверки не пройдены или конфликт нельзя безопасно разрешить, не объединяй изменения до устранения проблемы.
