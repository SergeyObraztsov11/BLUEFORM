# Проверки качества

Инструменты устанавливаются отдельно для корня, клиента и сервера. Нужен Node.js 24 или новее:

```sh
npm ci
npm ci --prefix client
npm ci --prefix server
```

Команды из корня проекта:

| Команда | Назначение |
| --- | --- |
| `npm run format:check` | Проверить форматирование Oxfmt без изменения файлов. |
| `npm run format` | Форматировать проект с помощью Oxfmt. |
| `npm run lint` | Проверить TypeScript и Vue через ESLint. |
| `npm run lint:fix` | Применить доступные автоматические исправления ESLint. |
| `npm run typecheck` | Проверить типы Express, тестов и Nuxt. |
| `npm run verify` или `npm run check` | Последовательно проверить форматирование, линтинг и типы. |

Перед проверкой типов генерируются Prisma-клиенты. Для генерации Nuxt использует технический URL, если `DATABASE_URL` не задан: генерация не подключается к базе. Сгенерированные файлы, зависимости, результаты сборки и lock-файлы исключены из форматирования.

Для проверки с запущенной базой и приложениями выполните `npm run test:contract`. Локальная проверка регистрации, сессий, корзины и оформления описана в [архитектуре API](API-ARCHITECTURE.md).

GitHub Actions запускает `verify`, затем поднимает изолированный Docker Compose и выполняет интеграционные проверки. Workflow работает с временными тестовыми настройками без секретов пользователя. Обязательный статус проверки для `main` настраивается отдельно в защите ветки GitHub; сам workflow не блокирует изменения.
