# Состояние приложения

В PostgreSQL применены миграции из `prisma/migrations`: категории, размерные сетки и размеры, модели, ткани, цветовые варианты, SKU, файлы и изображения, таблицы Better Auth, профиль и избранное. Seed в `prisma/seed.ts` создаёт согласованное дерево каталога: 27 категорий, 18 моделей, 26 цветовых вариантов и 129 SKU. Путь категории и её фасон описаны в `shared/catalog-categories.ts`; у модели в базе только `categoryId`, отдельного свободного поля `fit` больше нет.

Существующие фактуры остаются в `client/public/images`, а их пути указаны в `media_files` с источником `STATIC`. У 16 новых демонстрационных позиций фотографий нет и записей `product_images` для них не создаётся. Интерфейс подставляет локальный `client/app/assets/images/product-placeholder.webp`; это изображение не хранится в базе и не запрашивается у файлового сервиса.

Категории каталога обслуживает Express через прокси Nuxt; остальные маршруты каталога, корзина, избранное и оформление пока читают PostgreSQL через Nitro API. Описание запросов, примеров ответов и ошибок — на `/docs` (`/openapi.json`). `client/app/data/catalog-test.json` остаётся источником для seed, страницы его больше не импортируют. Категория, фасон и вложенное меню по-прежнему берутся из `shared/catalog-categories.ts`: отдельной колонки фасона в базе нет. Цена в базе хранится в копейках, API отдаёт рубли.

Гость узнаётся по httpOnly-cookie `bf_guest`. В базе лежит только SHA-256 этого секрета. Первое добавление в корзину или избранное создаёт `GuestSession`, корзину и избранное. После регистрации гостевая корзина и избранное переходят в новый аккаунт. Вход в уже существующий аккаунт оставляет корзину и избранное аккаунта, гостевые данные удаляются. Выход не переносит корзину и избранное аккаунта обратно в браузер.

Регистрация — почта и пароль через Better Auth, затем пятизначный код на Mailpit. Заказ создаётся без оплаты и доставки: цена и строки берутся из активных позиций корзины, остаток уменьшается в той же транзакции, корзина очищается. Если пользователь вошёл, у заказа сохраняется `userId`, а имя и телефон записываются в профиль.

В проекте подключены Pinia и модуль `@pinia/nuxt`. Сторы находятся в `client/app/stores`.

| Store | Ответственность | Сохранение |
| --- | --- | --- |
| `cart` | Позиции по паре «товар + размер», количество, удалённые строки и итог | PostgreSQL; гость — по cookie, аккаунт — по сессии |
| `favorites` | Карточки избранных цветовых вариантов | PostgreSQL; гость — по cookie, аккаунт — по сессии |
| `account` | Почта, имя и телефон подтверждённой сессии | Better Auth; стор только отражает `GET /api/account` |

Один товар может находиться в корзине в нескольких размерах; каждый размер учитывается отдельно. Позиция с количеством 0 остаётся серой на странице корзины для быстрого возврата, но не учитывается в сумме и не показывается в мини-корзине. Такая строка сохраняется после обновления страницы.

Категория, поиск, фильтры, сортировка и номер страницы остаются в URL каталога и уходят в `GET /api/catalog/products`: ответ — страница из 8 карточек и `total`. У размера в карточке есть остаток. Ошибки магазина имеют стабильный `code` из `client/server/utils/errors.ts`. Разделы каталога отдаёт `GET /api/catalog/categories`. Свои заказы читаются через `GET /api/orders`, профиль обновляется через `PATCH /api/account`. Открытое меню, предпросмотр корзины и поля окна входа относятся к интерфейсу конкретного компонента и не сохраняются в Pinia.

Пароли и коды подтверждения в сторы не попадают. Сессия Better Auth и гостевой секрет живут в httpOnly-cookie.
