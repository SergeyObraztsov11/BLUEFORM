# BLUEFORM — визуальная проверка лендинга

## Пакет 2: кабинет и оформление — 2026-11-02

Cursor реализовал композицию и тексты ведущего агента. Ведущий проверил изменения и реальные экраны, вернул повторные заголовки на исправление и принял результат после повторного браузерного прогона.

- Профиль — одна форма без панели «Всё под рукой», с сохранением и выходом. Email отображается как неизменяемое значение. Подтверждение сохранения исчезает при следующем редактировании.
- `/settings` возвращает временный 302 на `/profile`; ссылки на фиктивные настройки удалены из обоих меню аккаунта.
- Оформление — контакты и доставка слева, одна белая сводка справа. На телефоне порядок: поля, состав и итог, предупреждение об отсутствии списания, подтверждение. Общая сводка и её тип выделены без дублирования разметки.
- Подтверждение содержит один заголовок и основную кнопку открытия заказа. Детали показывают статус, дату, состав, контакты, адрес и трек-номер при его наличии.
- Браузерная проверка обнаружила, что `/orders/:id` показывал список вместо деталей. Cursor перенёс список из `pages/orders.vue` в `pages/orders/index.vue`. Прямой переход проверен повторно; административные маршруты уже имели правильную структуру.
- Ошибка выхода больше не скрывается: профиль сохраняется при отказе сервера, все места вызова обрабатывают ошибку.

### Проверки ведущего агента

В изолированном локальном аккаунте проверены сохранение профиля, серверная ошибка и сохранность полей, сброс подтверждения при редактировании, редирект настроек, меню аккаунта, отказ выхода и успешный выход. Проверены оформление после ошибки без потери адреса, двойная отправка (один POST), реальное создание тестового заказа, открытие деталей и вывод трек-номера из API, уведомления. Профиль, оформление и детали проверены на 320/390/768/1280/1440/1920 px без горизонтального переполнения; порядок блоков на телефоне проверен отдельно. Тестовый заказ отменён через API для восстановления остатка, затем только его аккаунт, заказ и письма удалены. Данные и корзина владельца не изменялись.

Административный список отдельно проверен на 390/1440 px; отказ выхода показывает ошибку, успешный выход открывает `/admin/login`.

`npm run verify`, `npm run build` и `npm run test:contract` (8/8) проходят. Визуальную приёмку выполнил ведущий по снимкам Chrome. Маска телефона и серверная нормализация остаются в пакете 3; карточки и главная — в пакете 4.

## Пакет 1: каркас и корзина — 2026-11-02

Реализован и принят первый пакет [структурной переработки](../planning/INTERFACE-PLAN.md). Композицию и тексты задал ведущий агент, Cursor выполнил код; ведущий проверил diff, реальные экраны и сценарии, вернул замечания и повторно проверил исправления.

### Результат

- Большие синие баннеры заменены компактным белым `ShopPageHeader`. Удалены повторные вступления и крупные линии над содержимым; полезные сообщения об ошибках товара сохранены.
- Меню «Главная / Женщинам / Мужчинам / Распродажа» по центру контейнера, логотип слева, действия справа. «Ткани» удалены из desktop/mobile меню. Мобильный режим действует до 1280 px, нижняя панель и отступ layout используют тот же breakpoint.
- В корзине сразу видны товары, счётчик и компактная белая сводка с одним итогом. Красное сообщение про обычный остаток удалено. Сводка скрывается после удаления последнего товара, восстановление остаётся доступным; счётчик учитывает видимые недоступные позиции.
- Избранное использует существующую товарную сетку каталога без бокового пересказа оттенков и отдельной дублирующей разметки товара. Пустые состояния сокращены до названия и перехода в каталог.
- Выбранные категории используют `cobalt`; фокус различим на синем фоне. Открытые слои хедера закрываются при смене desktop/mobile режима; форма авторизации сохраняется.

### Проверки ведущего агента

- Геометрия меню гостя и пользователя: 320, 390, 768, 1024, 1279, 1280, 1440 и 1920 px. На desktop центр меню совпадает с центром контейнера с допуском 2 CSS px; пересечений и горизонтального переполнения нет.
- Корзина, сетка избранного и ещё семь маршрутов (каталог, профиль, настройки, заказы, уведомления, оформление, отсутствующий товар) проверены на 320/390/768/1280/1440/1920 px. Всего 70 проверок геометрии. Первый товар в корзине при 1440×950 начинается на 201 px от верхнего края окна.
- В отдельной гостевой сессии проверены добавление, количество, смена размера, удаление последнего товара, скрытие сводки и восстановление. Проверены добавление/удаление избранного и пустые состояния. Корзина пользователя не изменялась.
- Проверены открытие мобильного меню и расширение окна, сохранение формы авторизации и введённого email при resize, прежний клик предпросмотра корзины и закрытие невидимого preview при смене режима.
- `npm run verify`, `npm run build` и `npm run test:contract` (8/8) проходят. В существующем контрактном тесте проверка заголовка оформления сделана нечувствительной к регистру; проверка запрета анонимного заказа сохранена.

## Архив: приёмка первой технической очистки — 2026-11-02

После этой проверки владелец указал на оставшиеся системные недостатки композиции: повторные вступления, одинаковые баннеры, лишние панели и слабую проверку форм. Повторный аудит подтвердил замечания; [новый этап плана](../planning/INTERFACE-PLAN.md#новый-этап--аудит-и-конкретный-чек-лист) открыт. Описанная ниже приёмка относится к предыдущей технической очистке, а не к окончательному качеству дизайна.

Выполнен первый этап [плана интерфейса](../planning/INTERFACE-PLAN.md). Стиль BLUEFORM сохранён. Cursor выполнил изменения, ведущий агент самостоятельно проверил код и вернул замечания по мобильным заголовкам, настройкам, размерам форм и возврату фокуса. Результат принят после исправлений.

### Что изменилось

- Палитра показывает ткани и названия без HEX и ложного перехода «Смотреть оттенок»; переход в каталог работает.
- _(Исторически.)_ В настройках остались фактические параметры, кабинет и выход. Неработающие будущие функции и бейджи удалены; ошибка выхода показывается пользователю. Позднее `/settings` сведён к редиректу на профиль.
- Убраны повторные подписи и дубли в футере; манифест согласован с широким каталогом.
- Длинные заголовки и поля авторизации помещаются на узких экранах; Escape возвращает фокус к кнопке открытия даже при быстром вводе во время анимации.
- У каталога есть повторная загрузка после ошибки; поиск без результата можно сбросить. Удалены неиспользуемые заглушки и вложенный `main` товара.

### Проверки

- В Orca Chromium выполнено 56 проверок: 14 маршрутов на ширинах 320, 390, 768 и 1280 px. Проверены главная, каталог, товар, избранное, корзина, оформление, профиль, настройки, заказы и детали, уведомления, отсутствующий товар, список и детали административных заказов. Переполнений документа и заголовков и сломанных загруженных изображений не обнаружено.
- В локальном браузере пройден путь: размер → корзина → избранное → оформление → подтверждение → просмотр заказа администратором → отмена с возвратом остатка. Проверены заполненное избранное и пустая корзина после заказа.
- В Chrome через Playwright на 320 px проверены регистрация, длинная почта, код из локального Mailpit и подтверждение аккаунта; выход, неверный пароль, Escape и возврат фокуса. Границы полей и кнопок сверены с границами диалога.
- Проверены мобильный фильтр наличия, пустой поиск и сброс. Ошибка загрузки каталога воспроизведена подменой ответа API на 503; после снятия подмены кнопка «Повторить» возвращает товары.
- `npm run verify`, `npm run build`, `npm run test:contract` (8/8) проходят. Первый запуск контрактных тестов во время перезапуска Nuxt завершился ошибками соединения; после готовности сервера повторный запуск успешен.

Проверка выполнена локально в Chromium/Chrome. Она не заменяет подготовку настоящих товарных фотографий, условий магазина и остальных пунктов MVP. Демонстрационные товары и изображения сохранены.

## Что изменено

- Правая вертикальная навигация заменена обычным белым хедером с названием, ссылками и кнопкой перехода к коллекции. На узком экране ссылки раскрываются через меню.
- Все основные блоки помещены в общий контейнер шириной до 1280 px. Хедер находится в этом же контейнере.
- Заголовок «ДЕНИМ ПО ТВОИМ ПРАВИЛАМ» расположен на самостоятельной кобальтовой панели рядом с фотографией; текст не перекрывает ткань.
- Высота первого кадра, манифеста и товарного блока привязана к высоте окна с верхними и нижними пределами. Это сохраняет ритм разворотов на ноутбуке и не делает кадры чрезмерно высокими.
- Хедер, каждая секция и футер вынесены в отдельные компоненты. Стили страницы собраны на Tailwind CSS 4 с фирменными цветами в теме.
- Тексты на странице приведены к русскому языку, заголовки и логотип очищены от точек. Описания объясняют крой, фактуру и варианты сочетаний. Второстепенные переходы удалены.
- Вместо системного шрифта подключён Golos Text с кириллицей. Для навигации и перехода к коллекции подключены угловатые Material Symbols Sharp; на странице используются только значки с конкретным действием.

- Переходы «СТУДИЯ» и «КОЛЛЕКЦИЯ» прокручивают соответствующие блоки ниже закреплённого хедера.
- Проверены загрузка Golos Text и отображение иконки на кнопке хедера.
- Три изображения загрузились. Горизонтальной прокрутки и ошибок консоли при проверке широкой версии не обнаружено.
- `npm run build` завершился успешно.
