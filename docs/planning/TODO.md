# BLUEFORM — задачи

## Текущая структура задач

Бизнес-решения и границы MVP определены в [плане MVP](MVP-PLAN.md). Текущий этап — [доработка интерфейса магазина](INTERFACE-PLAN.md).

У каждой задачи: ID, основной блок, ожидаемый результат, критерии приёмки, приоритет и статус. Если задача описана в плане этапа или MVP, оставляем ссылку вместо второго независимого чеклиста.

Приоритеты: **критично до запуска / нужно до запуска / можно после запуска**.

Статусы: **запланировано / в работе у Cursor / на проверке ведущего агента / на доработке / готово**. Готовность подтверждает ведущий агент после самостоятельной проверки.

| Блок                              | Содержание и текущие задачи                                                                                                              |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Дизайн — DESIGN                | Визуальный стиль, типографика, фото, композиция и общие элементы. Текущие задачи — в плане интерфейса.                                   |
| 2. UI/UX — UX                     | Навигация, выбор и покупка, мобильные сценарии и доступность. Текущие задачи — в плане интерфейса.                                       |
| 3. Магазин и содержание — CONTENT | Назначение страниц и блоков, полезные тексты, достоверные сведения. Интерфейс — в плане этапа; реальные товары и условия — в MVP.        |
| 4. Архитектура фронтенда — FRONT  | Компоненты, файлы, состояние, API и скорость. Проверяется при каждой задаче интерфейса.                                                  |
| 5. Архитектура бэкенда — BACK     | База данных, API, товары, остатки, заказы, административные функции. Текущие этапы — в MVP.                                              |
| 6. Безопасность — SECURITY        | Авторизация, права, персональные данные, секреты, входные данные и зависимости. Проверки перед запуском — в MVP.                         |
| 7. Тестирование и надёжность — QA | Сквозные сценарии, регрессии, браузеры, сбои и повторные действия. Текущая приёмка — в плане интерфейса.                                 |
| 8. Запуск и эксплуатация — OPS    | Окружения, публикация, мониторинг, резервные копии, восстановление, индексация и аналитика. Публикация отложена за пределы текущего MVP. |

## Прежние задачи и заметки

Ниже сохранена история прежних этапов. Она не определяет текущую очередь; сведения о реализации нужно сверять с кодом и планом MVP.

### Сделано для первой версии палитры

Взяли **каждый второй оттенок** из десяти на присланном референсе. На главной — карточки ткани с фотографией фактуры, цветовым образцом и русским названием (без HEX и без ложного CTA):

- 01 Dark Blue — **Тёмный синий** (`denim-midnight.webp`)
- 03 Indigo Blue — **Индиго** (`denim-indigo.webp`)
- 05 Medium Blue — **Средний синий** (`denim-coastal.webp`)
- 07 Sky Blue — **Небесный голубой** (`denim-sky.webp`)
- 09 Ice Blue — **Ледяной голубой** (`denim-icy.webp`)

Карточки листаются в Swiper. HEX остаётся во внутренних данных для образцов в фильтрах каталога, но не выводится покупателю текстом. Реальные цвета ткани нужно утвердить по физическим образцам.
